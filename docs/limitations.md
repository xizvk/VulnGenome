# Limitations and unsupported capabilities

- The implementation is an early controlled-fixture prototype, not a general binary invariant discovery system.
- The original experiment supplies capacity and argument role from `fixtures/contract.json`. Automatic inference accepts only a positive-size ELF `STT_OBJECT` whose one-byte store is proven by a narrow VEX pattern to use a zero-initialized local counter, increment that counter by one, and execute only under an unsigned `counter < first_sink_argument` check at entry and on the loop back edge. It requires a unique direct caller-to-sink call and preserved symbol metadata. Calls inside the sink, unclassified non-stack stores, unsupported VEX memory writes (`StoreG`, `CAS`, `LLSC`, or `Dirty`), false-edge paths that can reach the store, unrelated stores, multiple argument-indexed objects, ambiguous symbols, unsupported loop shapes, and stripped binaries abstain. Stack/local, heap, indirect, aliased, dynamic, and general allocation-size inference remain unsupported.
- Binary CFG/VEX depends on angr 10.0.4 importing successfully. Metadata-only PE/ELF parsing is not a substitute for disassembly.
- Function matching currently pairs only unique exact symbol names. It does not support robust stripped-binary matching or semantic equivalence claims.
- Patch evidence currently captures CFG branch-block counts and call-target count changes. It does not yet build data-dependence slices or normalize branch predicates.
- Bounds/range, integer representability, and one-bit guard properties have typed compilers. The automatic binary call-site verifier checks the actual first sink argument against an inferred extent only after the supported loop relation is recovered. Its `PROPERTY_HOLDS_WITHIN_MODEL` result is not a full memory-safety proof: analysis remains limited to reached caller paths, the supported VEX shape, Linux AMD64 ELF, and the recorded assumptions about ABI argument meaning and complete sink behavior.
- There is no LLM, RAG, CVE corpus, BinKit/Juliet integration, baseline execution, ablation, cross-architecture, or cross-implementation experiment.
- No real-world CVE sample has been verified or included. No research advantage, accuracy, or statistical improvement is claimed.
- The independent adversarial evaluation uses a small set of synthetic fixtures and one Clang/LLD configuration. Its counts validate these cases only and do not estimate real-world accuracy, compiler robustness, or cross-architecture generalization.
- The cross-optimization evaluation covers Clang/LLD 23.1.4 at `-O0`, `-O1`, `-O2`, `-O3`, and `-Os`, but the current VEX matcher recovered its supported stack-frame argument/index pattern only at `-O0`. The optimized builds therefore abstained; optimizer robustness is not established.
- Cross-build transfer is an experimental, hash-bound prototype. It transfers only an abstract sink-argument-versus-object-extent property and candidate semantic names; the target must independently recover object/store/guard/call/path evidence. O0 telemetry fixtures demonstrate this narrow check in both directions. All 38 matrix transfers to a distinct optimization build were inconclusive because target evidence was unsupported. This is not evidence of general transferability.
- Across the 48 repeated synthetic builds, the classifier made zero false-safe classifications, but it classified only 9/48 cases. That result is a property of this small corpus and must be read with its 39/48 abstentions, not as a general safety or accuracy estimate.
- Windows WSL access was denied. Zig provides a cross-compiler, but the produced ELF is analyzed on Windows and is not run.
- Ghidra, BinDiff, Diaphora, YARA export, and a dashboard are not implemented.
